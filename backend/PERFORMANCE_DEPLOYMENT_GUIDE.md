## Troubleshooting

### Issue: Migration fails with "index already exists"

**Solution:** Index might exist from manual creation. Drop it first:
```sql
DROP INDEX IF EXISTS idx_document_user_processed;
DROP INDEX IF EXISTS idx_document_upload_date;
DROP INDEX IF EXISTS idx_session_owner_created;
```

Then run migration again.

### Issue: Memory still high during document processing

**Possible causes:**
1. Multiple documents being processed simultaneously
2. Other parts of code holding references
3. Python garbage collection not running

**Solution:** Monitor with memory profiler:
```bash
pip install memory_profiler
python -m memory_profiler app/main.py
```

### Issue: Queries not using new indexes

**Possible causes:**
1. Database statistics out of date
2. Query planner choosing different plan
3. Small dataset (full scan faster than index)

**Solution:** Update statistics:
```sql
ANALYZE documents;
ANALYZE chat_sessions;
```

### Issue: OpenAI connection timeouts

**Check:**
1. Verify timeout set to 120s
2. Check document size (>1000 pages may need more time)
3. Verify network connectivity

**Solution:** Increase timeout if needed:
```python
timeout=httpx.Timeout(180.0, connect=10.0)  # 180s for very large docs
```
